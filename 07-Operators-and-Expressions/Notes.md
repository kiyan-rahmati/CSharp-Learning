# Lesson 07: Operators and Expressions

## Learning objectives

By the end of this lesson, you should be able to:

- Explain the core idea: Use arithmetic, comparison, logical, assignment, and precedence rules.
- Recognize when this concept is useful in a real application.
- Read, write, and reason about the related C# code.
- Identify common mistakes and test your own implementation.

## 1. Core concept

Use arithmetic, comparison, logical, assignment, and precedence rules.

The important goal is not memorizing syntax. Learn what problem this feature solves, what assumptions it makes, and how to decide when to use it. Keep the vocabulary in this lesson in mind when reading documentation or reviewing code.

## 2. Key concepts and syntax

+, -, *, /, %, ==, !=, &&, ||, !, ??

## 3. Step-by-step workflow

1. Read the example in `Program.cs` once without typing it.
2. Predict the output or behavior before running the program.
3. Type the example yourself, run it, and compare your prediction.
4. Change one input or condition at a time. Observe how the behavior changes.
5. Try an edge case (empty input, zero, negative value, duplicate, or a very large value—whichever makes sense for this topic).
6. Complete the practice task without copying the solution.

## 4. Example

See `Program.cs` for a small runnable demonstration. The code is intentionally compact: focus on the idea being taught rather than building a complete application in one file.

## 5. Common mistakes

- Treating syntax as the whole concept instead of understanding the reason behind it.
- Ignoring edge cases and assuming inputs are always valid.
- Naming variables vaguely (`x`, `data`, `thing`) when a meaningful name would help.
- Changing several parts at once, then not knowing which change caused a bug.
- Copying code without being able to explain each statement.

## 6. Practice

**Task:** Create a calculator that supports four operations and handles division by zero.

### Practice rules

- First write the steps in plain English or pseudocode.
- Implement the solution yourself in a separate section or file.
- Test at least three cases: normal, boundary, and invalid/unexpected.
- Keep the code readable. Use names that describe the data or action.
